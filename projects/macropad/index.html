Macropad

Nothing built. Hardware on the desk, notes below.

A numpad with a knob, reprogrammed into a control surface for working with coding agents — and one key that has to tell the truth about whether my microphone is live.

The keyboard is a Keychron K0 Max: 27 keys, a macro column, a rotary knob, per-key RGB, and QMK firmware, which is the part that matters. QMK means the firmware is mine. Per-key RGB means a single key can be an indicator rather than decoration.

Why a keyboard, for this

Most of my day is now a loop: a model proposes something, I look at it, and I accept it or I don't. The proposing is the part everyone talks about. The accepting is the part that actually takes the time, and it is almost entirely two decisions repeated a few hundred times a day — yes, do that and no, stop.

Two decisions repeated a few hundred times a day is what a physical key is for. That is the whole thesis, and it is small enough to be honest about.

What is actually broken

I went looking for what other people had built and found that most of it exists already — a first-party macro pad from OpenAI, a sixteen-key board for Claude Code, session-mirroring daemons, wearable pagers, an official Bluetooth API from Anthropic. Which is useful, because it means the question stops being can this be built and becomes which of these pains is real.

Ten of them, each with what I think the fix is. The products are evidence, not the point.

The agent frees your hands and takes your attention

This is the one I had wrong. An agent that works for twenty minutes should let you leave, and it doesn't, because you can't predict which minute it will need you. A desktop notification is no help: it brings you back to the screen, not back to the room.

So the device is not primarily an input. It is a light you can see from the kitchen. Everything else on this page is secondary to that.

You cannot tell which session wants you

Running several agents at once is now ordinary — worktrees made it safe and every major tool ships parallelism. But the screen shows you the front window, and finding the blocked one means cycling through the rest.

One slot per session, state as colour. Existing daemons run eight states — thinking, tool running, blocked, stalled, error — and blocked is the only one you actually need to see from across a room.

Approving is already too fast

Anthropic's own telemetry has users approving around 93% of permission prompts. A study of 409,000 decisions found one dangerous request in three waved through — scope violations reaching for cloud credentials missed a third of the time, and one malicious script approved about two thirds of the time with its payload printed on the screen above the prompt.

This is the finding that changes the design. A big fast ACCEPT key makes the number that is already too high go higher. Whatever this device is for, it is not for approving things more quickly.

The fault is sameness, not speed

A destructive command and a file read arrive in the same box, in the same words, in a stream of things that were all fine. The rare one is camouflaged by the common ones.

Give the rare decision a different physical shape — a different key, a different colour, a deliberate two-handed action. Fewer gates, and the ones that remain not resembling each other.

There is a line a key must not cross

The commercial pads bind FIX, TEST, EXPLAIN, REVIEW and an auto-accept toggle to single keys, and the first four are obviously right.

A key is right for anything you would otherwise retype and wrong for anything you would otherwise think about. That is the whole rule, and it puts approve on the far side of it.

A mode you have to remember is a mode you will be wrong about

Auto-accept and plan mode are both states that change what happens next and neither is visible once you have looked away.

A latching key with a light. The mode stops being something you recall and becomes something on the desk.

The interesting direction is the other one

I assumed a person pressing keys at an agent. Elgato went the other way in May 2026: Stream Deck became an MCP server, so an agent can trigger actions, and the user curates exactly which actions exist to be triggered.

The surface becomes the permission model. A policy file you can see and point at, and a very good answer to the problem two sections up.

The bottleneck moved and the hardware has not

When delegating gets cheap, the scarce thing stops being code and becomes review capacity, CI minutes and the attention to decide what merges.

Which suggests instrumenting the queue rather than the generator. How many things are waiting on me is a more useful number than how many agents are running.

The transport problem mostly dissolved

I had this project blocked on whether raw HID crosses a wireless link, because Keychron's own configurator only works over a cable. That is still true, and it now only matters for one of the three things I want.

Anthropic shipped a Bluetooth API for Claude's desktop apps — Nordic UART, newline-delimited JSON, session status and permission requests with a tool id you answer by writing back. Wireless, first-party, no host agent. Undocumented and explicitly unsupported, which is a different kind of risk from a soldering one.

Do not build on somebody's local API

The original plan read Teams' mute state from the local API every Stream Deck button used. Microsoft retired it on 30 June 2026 with no replacement, which is the whole argument in one date.

Mute at the operating system's capture device and read the same device back. One copy of the truth, owned by the thing doing the muting, and it works in every application at once because it is not in any of them.

Order of work

  1. The keystroke layer, and use it for a fortnight. A month of use says which keys were wishful thinking, and it needs nothing built.
  2. The light, over Bluetooth: blocked or not blocked, visible from the kitchen. This is the actual project and everything above says so.
  3. One latching key for auto-accept, because it is an evening's work.
  4. Only then decide whether per-key colour is worth a cable, and whether the pad should be something the agent asks rather than something I press.
  5. Come back and replace this page with what actually happened.
